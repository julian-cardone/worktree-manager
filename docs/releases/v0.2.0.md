## New

- **`wt remove <task> --delete-branch` abandons a task.**
  It removes the task's worktree with all of `wt remove`'s usual checks, then deletes the task's branch even though it hasn't landed.
  It also works for a task whose worktree was already removed.
  It prints the command that restores the deleted branch.

## Safety

`--delete-branch` is the first way `wt` deletes a branch that hasn't landed, so it is deliberately narrow:

- It refuses before removing anything, and again right before deleting the branch, if the branch is the integration branch or could become it, isn't an exact local branch `wt new` could have created, differs only in case from another branch, is checked out in another worktree, or is being rebased.
- It deletes the branch only after the worktree is verified gone, and only at the commit it checked (`git update-ref -d <ref> <tip>`, never `git branch -D`), so a branch that moved meanwhile is kept.
- It refuses while the task's worktree has a detached HEAD, which would otherwise have deleted the branch and left a worktree `wt` could no longer find, and says how to check the branch out there again.
- For a task with no worktree, it requires the repository's `wt` container to exist and be verifiably this repository's, the only evidence that `wt` manages tasks there.

All other commands behave as in 0.1.0.
